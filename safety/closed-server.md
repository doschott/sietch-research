# Closed-server boundary

This file restates the server limit in the September 2026 request. It does not add a server, a hostname, or a password. None of those belong in a public repository.

## The server the request asks for

One battlegroup, with all of the following:

- self-hosted by the project
- using Funcom's official self-host tools
- invite-only
- passworded
- not listed publicly
- operated by the project

## Servers the request does not ask for

- official servers
- a public or rented private-server World shared with other communities

## People

Agents on that battlegroup would interact only with the research group. They would not contact players outside that group in the Deep Desert or in social hubs.

The size of the research group, and how invitations would be sent, are open questions. This repository does not publish an invite list.

## Status of the server

No research battlegroup is being used by agents from this repository. Permission is pending. The sandbox does not open a network connection to a game server. A contributor should not add a server address, a password, or a screenshot of a server browser to the repo. Passwords are already excluded by [../CONTRIBUTING.md](../CONTRIBUTING.md) and by `.gitignore`.

## If permission is refused or ended

The agents stay out. The closed-server plan stops. The sandbox can remain in the repository as a methods exercise. Funcom's right to refuse, pause, or end the exception is part of the request and does not depend on this file.

## If permission is granted with conditions

Those conditions become part of the boundary, including conditions on who may be invited, how the server is run, and when it must come down. **Proposed, pending Funcom review:** record the conditions in a short addendum next to this file before the first agent session, and treat a mismatch between the live server and that addendum as a stop under [stop-procedures.md](stop-procedures.md).
